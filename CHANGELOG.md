# Changelog

## Unreleased

### Added
- Golden fixtures freezing the Python reference behavior under `native/golden/` (RNG traces, Snake transitions under the greedy policy, an MCTS oracle, and 10,000 tabular Q-learning updates), generated by `tools/native_reference.py`. First step of the native C++ engine; regeneration is byte-identical.
- CPython-compatible random number generator in C++ under `native/`, verified against the golden RNG traces (5,700 operations, zero mismatches), including snapshot and restore.
- C++ Snake simulator mirroring the Python environment transition for transition (110,035 differential transitions across grid sizes, zero mismatches).
- C++ policies (random, greedy, Q-table) and a tabular Q-learning agent; 10,000 golden updates replay bit-exact, and greedy and Q-table actions match the Python policies on 34,532 live states each.
- C++ Monte Carlo tree search matching the Python implementation: oracle cases exact, 1,000 fuzz searches with zero action mismatches, and 2,333 root children values bit-exact.
- Optional pybind11 backend (`narcade_native`) behind `NARCADE_NATIVE=1`; Python stays the default. The backend check compares RNG, Q-learning, Snake, and MCTS against Python with zero mismatches, and the test suite skips cleanly when the extension is not built.
- Native benchmark suite (`narcade_bench`) with deterministic, checksummed workloads for environment steps, RNG draws, MCTS searches, and evaluation episodes. Rates are recorded, not published as claims.
- Native DQN inference: the 436-feature encoding and the JSON weights forward pass in C++. Action agreement on 13,824 harvested states is 13,824 of 13,824 against the PyTorch reference, with max logit difference under 1e-5. Inference only; training stays in Python.
- Native evaluation engine reproducing `scripts/evaluate.py` exactly (paired seeds, shared MCTS player, summary statistics, Elo, head-to-head): 200 of 200 episodes exact and every reported value bit-exact. The DQN player is out of scope for the native evaluator, and its report says so in a scope field.
- Native Q-learning trainer reproducing `scripts/train.py` bit-exact, including the full 30,000-episode default protocol, learning curves, checkpoint Elo history, and the policy file. Its output matches the committed `runs/` artifacts value for value.
- Native move-level trace instrumentation reproducing `scripts/analyze.py` (action mix, death causes, food efficiency) exactly for all four policies, matching `runs/moves.json` value for value.
- Differential testing converted from live Python fuzz drivers to frozen golden corpora checked by the C++ runners (111,032 Snake transitions, 36,129 policy states, 1,039 MCTS searches), with a regeneration check that re-derives the corpora from the Python reference and byte-compares them. Language snapshot (2026-10-23, repository Linguist accounting): C++ 209,463 bytes, Python 184,759 bytes.
- Docs: corrected the greedy and DQN evaluation means in the README evidence table (19.89 and 5.39, matching runs/eval.json); fixed two stale references (the DA4 findings pointer and a retired-driver mention in tools/native_reference.py).
- Native verification hardening: the DQN checker now fails when the max logit difference exceeds its 1e-5 band (previously reported only); the dqn_check CTest registers against any Python with torch instead of a machine-specific path; new meta_check CTest verifies the golden files' SHA-256 hashes against meta.json.
- CI: added a separate Native workflow that builds the C++ engine and runs the CTest suite (corpus checks, regeneration, meta hashes, DQN gate) on pushes and pull requests; eval_fuzz is excluded there for runtime and remains a local gate.
- CI: the Native workflow now installs pybind11, so its build compiles the `narcade_native` extension, and a final step runs the adapter parity tests (`tests/test_native_backend.py`) against the built extension; the five extension-dependent tests no longer skip in hosted CI.
- Docs: the native RNG header now states its supported domain explicitly (int64 seeds, getrandbits widths 0 to 64, randint spans that fit in int64), which is narrower than CPython's random.Random by design.
- Docs: the README now carries the native C++ engine throughout: a C++ 20 badge, the intro, a native parity row in the evidence table, a native node in the design diagram, native build and test commands, and the repository map.
- Fix: the native DQN parity checker now rejects nonfinite logits outright instead of letting a NaN be swallowed by the running maximum; the finite check runs on both native and reference outputs before any difference is taken.
- Tests: golden corpus counts are now recounted from the corpus files themselves by a corpus statistics check and compared against meta.json, which must also carry exactly the expected count keys.
- Tests: MCTS maze-mode (wall) searches now have frozen parity coverage. A new golden corpus (`native/golden/mcts_wall_cases.txt`) replays 404 searches under the browser game's maze wall layouts (977 root children, bit-exact), including crafted cases where the wall geometry forces the action and a shared-player session for the RNG lifecycle under a wall set. The runner protocol gains a WALLS command, and the golden fixture set moves to golden-v3.
- Native verification: the corpus statistics checker is ported from Python to C++ (`native/tests/corpus_stats_check.cpp`, registered as the corpus_stats_check CTest); it performs the same 21-count recount of the golden corpus files against meta.json.
- Tests: the native evaluator now has a frozen regression subset for hosted CI (`eval_regression` CTest): Python-reference results for seeds 5000-5002 across all four non-neural players (per-episode scores and steps, summaries, Elo, head-to-head) are frozen in `native/golden/eval_regression.json`, outside the meta.json corpus accounting, and replayed exactly by a native checker on every CI run. The full `eval_fuzz` differential check remains a local gate, and changes to native evaluation code require a documented local `eval_fuzz` run.
- Docs: README header rebuilt with a centered title, a badge row (Python CI, Native CI, license, Python, C++20, stack) and action buttons for the game, the dashboard, the method, the recorded results and the run-locally section. The native engine is now described as an included optional backend rather than a mirror, the design diagram node is renamed to match, the native build snippet uses the same `native/build` path as the Run locally section, and the text was tightened throughout. No results, protocols or limitations changed.


## v1.3.0

### Added
- DQN failure diagnosis (`scripts/diagnose_dqn.py`, DA4). Instrumented
  training with a fixed compute budget (60k steps, 3 seeds each) across
  four variants: baseline DQN, double-DQN, reward-shaping removed, and
  supervised imitation of the greedy policy. Logs Bellman targets, TD
  loss, Q magnitudes, epsilon and death rates to
  `runs/da4_diagnosis.json`. Findings: DDQN
  does not help (not overestimation bias); removing shaping collapses
  learning to ~0.3 (shaping is load-bearing); the supervised clone
  reaches near-zero training loss but scores only ~3.7/20 on fresh
  seeds (the MLP memorizes flat pixels instead of learning spatial
  abstractions, so the representation is the bottleneck); 100% death
  rate with Q-values saturated at death magnitude. Scaling the MLP
  will not close the gap.

### Tests
- 5 new regression tests in `tests/test_diagnose_dqn.py`; full suite
  32/32 green.

## v1.2.0

### Fixed
- Evaluation now pairs agents by identical episode seeds: every agent plays
  the same explicit seed list for the ELO and head-to-head tables, instead of
  MCTS running on seed0=7000 while others used 5000 with truncated arrays
  mislabeled as paired.
- Larger independent per-agent evaluations are retained but reported
  separately (`scores_independent`), never mixed into the paired stats.
- `scripts/evaluate.py` no longer imports torch at module load; the DQN
  policy imports it lazily, so the paired-seed logic is testable without
  torch.

### Tests
- 2 new regression tests in `tests/test_evaluate.py`; 23/23 runnable tests
  green.

## v1.1.0

### Fixed
- A completely filled board is now an explicit win: eating the last food ends
  the episode with reason "win" and a well-defined terminal observation,
  instead of raising TypeError when the state encoder unpacked the missing
  food position.
- Stepping after a win raises a clear error (call reset() first).

### Tests
- 2 new regression tests in `tests/test_snake.py`; 21/21 runnable tests green
  (DQN tests require torch, unavailable in this environment).
