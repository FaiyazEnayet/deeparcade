# Changelog

### Added
- Native tournament and Elo runner (`narcade_tournament`): repeated round-robin rounds of paired episodes between all five players, with Elo carried across rounds, per-pair win/draw/loss records, and a JSON standings report (default `runs/tournament.json`). The shared rules mirror `scripts/evaluate.py` exactly (a match is a paired episode on a shared seed, higher score wins and equal scores draw; Elo starts at 1200 with K = 32 and sequential in-place updates in episode-major, pair order); the multi-round structure, records, and standings are new, and the report says so in its scope field. The pro player plays through the native DQN inference module over the committed JSON weights, so the tournament is the first native runner to cover all five players. Verification: Elo unit tests against hand-computed values (even win, draw, favorite-win delta, a scripted three-player sequence, standings tie-breaks); a frozen two-round tournament replayed by the `tournament_regression` CTest and byte-compared against `native/golden/tournament_standings.json` (outside the meta.json corpus accounting, like the evaluation regression freeze); and spot parity against `runs/eval.json`: the four non-neural players' episode scores on the frozen seeds equal the recorded paired scores, and the native Elo engine fed the recorded paired scores for all five players reproduces the stored Elo exactly. Pro's native episode scores are not claimed equal to Python's (its float32 forward pass accumulates in its own order); only the Elo processing of scores is parity-checked for pro.
- Versioned DQN checkpoint schema (schema_version 1) for the JSON weights export in scripts/train_dqn.py: export_weights now records the encoder name and revision (encode_dqn revision 1), the float regimes (weights stored as float32, browser parity declared in float64), a SHA-256 over the canonical weights payload, and metadata (training args, data key range, code commit). load_checkpoint is the strict inverse back to PyTorch: it validates the document before building any tensor (supported schema version, exact layer shapes, every value a finite number, weights hash match on versioned documents) and fails closed with CheckpointError on a corrupt checkpoint. scripts/evaluate.py DQNPolicy loads through the same strict path. The committed runs/dqn_weights.json is unchanged (it is a legacy schema 0 export) and is now described by runs/dqn_manifest.json: artifact SHA-256 b171d8a20e99e2ad4c472f03a940c83399570eb04f253d8da4aa299df57c7861, weights payload SHA-256 704e56c763985c31463b90939fd46394a5f79bfed70b37e7de336053efd28c61, training steps 300000, episodes 6984, seed 11, episode seed range [11, 6994]. Note: a float32 PyTorch evaluation differs from the browser export by up to 3.55e-06 on the same fixture, from float32 accumulation alone; greedy actions still agree on all 36 observations.

First step of the native C++ engine; regeneration is byte-identical.

## v1.3.0

### Added
- DQN failure diagnosis (`scripts/diagnose_dqn.py`, DA4). Instrumented
  training with a fixed compute budget (60k steps, 3 seeds each) across
  four variants: baseline DQN, double-DQN, reward-shaping removed, and
  supervised imitation of the greedy policy. Logs Bellman targets, TD
  loss, Q magnitudes, epsilon and death rates to
  `runs/da4_diagnosis.json`. Findings: DDQN
  does not help (not overestimation bias); removing shaping collapses
  learning to ~0.3 (shaping is load-bearing); the supervised clone
  reaches near-zero training loss but scores only ~3.7/20 on fresh
  seeds (the MLP memorizes flat pixels instead of learning spatial
  abstractions, so the representation is the bottleneck); 100% death
  rate with Q-values saturated at death magnitude. Scaling the MLP
  will not close the gap.

### Tests
- 5 new regression tests in `tests/test_diagnose_dqn.py`; full suite
  32/32 green.
